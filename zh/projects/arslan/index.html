它怎么运作

  1. 01

    说出要做的事

    在同一个对话里打字或说话。开始之前，Arslan 先写下怎样算完成。

  2. 02

    放到后台去做

    任务在后台跑，你照常聊天；它有自己的预算、检查点和停止按钮。

  3. 03

    每个动作都过闸门

    命令在沙箱里运行，按允许 / 询问 / 禁止判定；动你东西的操作先问你，Mac 或 iPhone 上都能答。

  4. 04

    核对过再交付

    逐条核对完成标准，结果标成完成 / 部分完成 / 卡住 / 已停止，附上文件和步骤。

难在哪，怎么解决的

说一次，然后继续聊。

要做的事应该离开对话去做，而不是把对话卡住：任务放到后台，聊天照常，结果核对过再回来。

  1. 做到一半停下的活，比不做更糟

    难在哪
    后台作业最初和一次聊天回答共用同一份预算，用完就被直接掐断。调研类的活经常做到一半，什么结果都没留下。
    我怎么做
    给每个作业单独的预算档位。到了档位，Arslan 停止继续查找，用已经拿到的内容把结果写出来；只有停不下来的作业才会在 1.5 倍处被拦下。
    结果
    随 0.1.43 发布；卡片会写明哪个额度用完了、怎么继续。

  2. 「做完了」要核对，不能只是嘴上说

    难在哪
    让 Agent 自己宣布「完成」很容易，但这样的结果很难让人放心。
    我怎么做
    每个作业开始前先写下「怎样算完成」；结束后逐条核对，结果标成「完成 / 部分完成 / 卡住 / 已停止」。
    结果
    每张作业卡上都能看到，标准逐条变成「达到」。

  3. 从来没跑过的安全测试

    难在哪
    Arslan 只在 macOS 上发布，但 CI 跑在 Linux 上。25 个只在 macOS 上生效的测试，其中 3 个是沙箱逃逸检查，一次都没真正跑过。
    我怎么做
    把 macOS 加成必过的 CI 检查，并逐个验证四项必过检查失败时确实会拦住合并。
    结果
    0.1.55 的 CI 共 6,443 个后端测试，另有 49 个只在 macOS 上的用例必须零跳过；生成的 Python 在禁网的内核沙箱里运行。
