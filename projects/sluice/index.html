How it works

  1. Arrange the system

    The player changes the allowed controls before resolving a day.

  2. Run the day

    The core advances scheduled units of water through a defined tick order.

  3. Read the outcome

    The simulator records deliveries, releases, flooding and unmet needs.

  4. Adjust & retry

    The UI animates the recorded moves and exposes the resulting state for the next decision.

The hard parts, and what I did

Plan the water. Understand the consequences.

Turn supply and timing into a puzzle that can be planned, played through and inspected one step at a time.

  1. Know a level is fair before anyone plays it

    The problem
    In a water-routing puzzle it is easy to ship a level that cannot be won, or one that can be won by accident.
    What I did
    A pure-Swift core with a uniform-cost solver. It keeps “unreachable” (a design problem) separate from “gave up” (a budget problem), and reports the cheapest winning plan day by day.
    Result
    Every level file can be checked from the command line before it reaches the app.

  2. Find the fun before polishing

    The problem
    A correct simulation is not the same as a good game.
    What I did
    A lab menu runs three rule sets on the same map: the baseline, a planning variant with a preview, and a real-time variant where you drag canals.
    Result
    Which version continues is decided by play-testing, not by the spec.
